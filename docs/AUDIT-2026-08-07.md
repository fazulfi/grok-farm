## 1. Ringkasan Eksekutif

Pipeline **farm → import → inject ke 9router** masih arsitektur yang benar dan layak dipertahankan.
Yang **usang** ada 3 komponen taktis: (1) Turnstile solver click-only, (2) sumber email IMAP, (3) akuisisi token loopback PKCE.
Ketiganya punya pengganti yang terbukti jalan di ekosistem: **turnstilePatch extension + MAILLDEZ temp-mail + OAuth device-code**.

> Tambahan kritis: model bernilai (grok-4.5, grok-build) digerbang di belakang **SuperGrok / X Premium+ subscription**.
> Akun free yang di-farm sekarang nilainya turun drastis (kena spending-limit `issue #26847`, permission-denied di `api.x.ai`).

## 2. Bukti Probe Live (2026-08-07)

| Probe | Hasil | Arti |
|---|---|---|
| `GET https://auth.x.ai/.well-known/openid-configuration` | 200 — **`device_authorization_endpoint: https://auth.x.ai/oauth2/device/code`** | Device-code = jalur OAuth resmi xAI |
| **`GET https://auth.x.ai/oidc/.well-known/openid-configuration`** | **200 — path inilah yang lolos Cloudflare** (tanpa `/oidc/` = 403). `grant_types_supported` termasuk `urn:ietf:params:oauth:grant-type:device_code`, `code_challenge_methods_supported: [S256]`, `token_endpoint_auth_methods_supported: [client_secret_basic, client_secret_post, none]` | Konfirmasi live: **public client + PKCE S256 + device_code grant didukung penuh** |
| `POST auth.x.ai/oauth2/device/code` (client_id `b1a00492...`) | **200** → `{device_code, user_code, verification_uri: accounts.x.ai/oauth2/device, verification_uri_complete, expires_in: 1800, interval: 5}` | Flow device-code hidup, client public |
| `POST auth.x.ai/oauth2/token` (device_code, belum approve) | 200 → `{"error":"authorization_pending",...}` | Token poll endpoint valid |
| `GET https://grok.com/device` | 200, ~483KB | Halaman device CLI live |
| `accounts.x.ai/sign-up` / `oauth2/device` | 403 Cloudflare | Signup butuh browser real (Turnstile) |

**Scope yang didukung auth.x.ai** (live, OIDC `/oidc/`):
`openid, profile, email, offline_access, grok-cli:access, team:read, org:read, api:access, grok-plugins:access, conversations:read, conversations:write, workspaces:read, workspaces:write`

**Catatan akses:** discovery **wajib** path `/oidc/.well-known/openid-configuration` (tanpa prefix 403).

## 3. Temuan Metode Lama (farm.py v2.3.2)

| Komponen | Cara lama | Kelemahan vs realita |
|---|---|---|
| **Turnstile** | Camoufox, click-only, semaphore `TURNSTILE_PARALLEL=1`, slice 25s | CF makin ketat; click-only sering `Verification failed`; parallel >1 bikin makin rawan |
| **Engine browser** | Camoufox (XPCOM) — wajib non-root, binary besar | Fragile di VPS; `--load-extension` gak didukung penuh seperti Chrome |
| **Email OTP** | IMAP Gmail (App Password) + plus-trick/catch-all `markettabrak.*` | Butuh inbox rahasia; rate limit Gmail; identitas terlacak |
| **Akuisisi token** | OAuth authorize loopback `127.0.0.1:56121` + PKCE (butuh callback server) | Loopback callback pusing di VPS headless; gak headless-friendly |
| **Output** | JWT `access_token` + `refresh_token` | Free-tier JWT nilainya rendah; refresh gak dipelihara (out of scope) |
| **Monetisasi** | Inject `grok-cli` + `xai` dari akun free | Model bernilai digerbang subscription; free kena spending limit |

## 4. Metode Baru (target adaptasi) — terbukti di ekosistem

### 4.0 Realita monetisasi (2026-08) — DECISIVE
- **xAI API (console.x.ai)** → pay-as-you-go, akun baru ~$25 kredit promosi (expire 30 hari) + $150/bln bila opt-in data-sharing. **Tidak butuh subscription.**
- **Grok Build/CLI (`grok-cli:access`)** → **butuh SuperGrok/X Premium+**; session OAuth menumpang kuota subscription (`grok-4.5` → `grok-4.5-build`, request "rides your SuperGrok quota").
- **Free tier** → cuma ~10 prompt/2 jam, **tanpa Grok 4/4.5**, tanpa `grok-cli:access`.
- **Implikasi farm:** token OAuth dari akun free ≈ nilai rendah. Jalur yang masih cuan: akun console baru dengan $25 promo, atau akun subscription. Audit ulang target farm.

### 4.1 Turnstile — KOREKSI KRITIS (2026-08-07): turnstilePatch bukan lagi solusi
**BUG sudah mati.** Chromium issue **#40280325** (screenX==clientX saat click CDP) **di-fix Google Sept 2025** lewat CL 6917162 ("Fix screen coordinates to avoid automation detection", rilis ~Chrome 131/132). Sumber: https://issues.chromium.org/issues/40280325 · https://chromium-review.googlesource.com/c/chromium/src/+/6917162
- **Implikasi:** di Chrome modern, turnstilePatch malah MENIMPA nilai screenX/Y yang sudah benar → anomali JS yang bisa di-fingerprint. Ia bukan lagi pembeda.
- **Yang beneran menentukan lolos Turnstile 2026** (cross-source: scrapfly, humanbrowser, ianlpaterson): *residential IP reputation + konsistensi UA/IP/TLS + `channel='chrome'` (bukan Chromium build) + **headed/xvfb***.
- **Rekomendasi driver:** `nodriver` (CDP murni, Chrome system) / `patchright channel='chrome'` (fork Playwright stealth) — menang di benchmark 2026. **Camoufox** masih oke utk fingerprint keras (lambat).
- `turnstilePatch/` di repo dipertahankan **hanya sebagai fallback/eksperimen** (`V2_TURNSTILE_PATCH=1/0`), bukan solusi inti.
- Verifikasi empiris ulang di accounts.x.ai dua varian (dengan/tanpa extension) sebelum cutover.

### 4.2 Email — MAILLDEZ-compatible temp-mail API
- `GET /api/session` → `sessionId`; `POST /api/inboxes` (pilih domain, round-robin) → `address`; `GET /api/inboxes/{addr}/messages` → cari OTP.
- Regex OTP: `code:\s*([A-Z0-9]{3}-[A-Z0-9]{3})` atau `code:\s*([A-Z0-9]{6})`.
- Ganti IMAP Gmail → API temp mail: lebih cepat, parallel-friendly, gak kena rate limit inbox utama.

### 4.3 Akuisisi token — OAuth device-code (resmi, live)
- `POST auth.x.ai/oauth2/device/code` → `{device_code, user_code, verification_uri_complete, expires_in: 1800, interval: 5}`.
- Buka `verification_uri_complete` di browser (yang udah login/SSO) → halaman `accounts.x.ai/oauth2/device?user_code=...` → tombol **Continue** → consent **Allow**.
- Poll `POST auth.x.ai/oauth2/token` `grant_type=urn:ietf:params:oauth:grant-type:device_code` → `authorization_pending` sampai user approve → lalu `{access_token, refresh_token, ...}`.
- **Cocok untuk headless / VPS / automasi.** Tidak perlu callback server.

### 4.4 Integrasi 9Router (dari dzDev37)
- `POST /api/auth/login` (password dashboard)
- `GET /api/oauth/grok-cli/device-code` → `{device_code, codeVerifier, user_code, verification_uri_complete}`
- Inject SSO cookies ke browser context → buka verify URL → klik `Continue` → `Allow` → poll `/api/oauth/grok-cli/poll` sampai `success: true`.
- **Catatan:** endpoint 9router `device-code`/`poll` di atas adalah milik **9router-mw/ind** — validasi endpoint aktual di host gateway saat integrasi.

## 5. Rekomendasi Implementasi

### Opsi A (disarankan) — modul paralel `farm_v2.py`
- Tulis ulang flow signup + token acquisition dengan metode baru, **tanpa menyentuh** `farm.py` yang mungkin hidup di fleet.
- `turnstilePatch/` di-copy ke repo (plaintext, MIT).
- Output tetap kompatibel: `email|password|access|refresh` + simpan SSO cookies untuk inject device-code 9Router.

### Opsi B — patch inkremental `farm.py`
- Ganti Camoufox → Playwright Chrome channel; ganti Turnstile solver → turnstilePatch; tambah device-code fallback.
- Resiko: merusak pipeline yang berjalan di production fleet.

**Rekomendasi Hiyuki: Opsi A** — aman, teruji terpisah, tinggal cutover.

## 6. Risiko & Mitigasi

| Risiko | Mitigasi |
|---|---|
| xAI makin ketat (rate limit, device fingerprint) | Proxy non-EU (residential) per browser; jangan hammer 1 IP |

| 9router API berubah | Validasi endpoint saat integrasi; jaga backward-compat |
| MAILLDEZ gak tersedia | Fallback: IMAP Gmail (mode lama tetap ada di farm.py) |
